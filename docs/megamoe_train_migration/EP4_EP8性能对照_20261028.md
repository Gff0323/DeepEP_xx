# MegaMoE BF16：EP4 / EP8 同输入性能对照

日期：2026-10-28。用途：公开协作分支的迁移复核记录，**不得进入 main 或 upstream 正式 PR**。

## 结论与范围

在同一台空闲 Ascend950 的相同卡组上完成两组 BF16 balanced 场景的完整 ABBA 对照。
两版全部输入、输出 Y、四项梯度的完整 SHA256 一致；每个 candidate 窗口先通过此检查
再开始计时。全部窗口计数正确、输出及梯度 finite，没有放宽阈值或修改 kernel。

下表主指标为：每次采样先取所有 rank 的最大 Event 耗时，再取窗口 p50；同版本两个
窗口的 p50 取算术均值。变化 = 迁移版 / 源版 - 1，负数更快。保留小幅变化，不将其
自动当作稳定收益，也不由本表声称所有路由、配套或设备上都无回归。

| 场景 | 阶段 | b8cff148 p50 / ms | 迁移版 p50 / ms | 迁移版耗时变化 |
| --- | --- | ---: | ---: | ---: |
| EP4 K3 | 前向 | 23.622560 | 23.644289 | +0.092% |
| EP4 K3 | 反向 | 47.611423 | 47.705928 | +0.198% |
| EP8 common | 前向 | 29.169566 | 29.127620 | -0.144% |
| EP8 common | 反向 | 60.032446 | 59.853201 | -0.299% |

本次 p50：EP4 前向 +0.092%、反向 +0.198%；EP8 前向 -0.144%、反向 -0.299%。
两组 allocator 峰值和 SHMEM 窗口容量均相同。两组性能接近；EP4 前向的 AB/BA
方向反转，不能把这些微小差值当作稳定收益或稳定回退。

只有每场景两个 source / 两个 candidate 短窗口。结合后面的 p95、正反序方向和
窗口波动判断；前向与反向分开计时，二者之和不是实测训练 step。

## 输入和测量方法

| 场景 | EP | 每 rank M | H | F | 每 rank 专家 | TopK | 保存 | clipping |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- | ---: |
| K3 | 4 | 8192 | 3584 | 3072 | 7 | 16 | bf16 | 0 |
| common | 8 | 4096 | 7168 | 4096 | 4 | 16 | bf16 | 0 |

每 rank 固定种子 `20261027 + rank`。X 为 BF16 正态输入乘 0.1，W1/W2 乘 0.01；
TopK 权重为 softmax 后转 BF16，dY 为 BF16 正态输入乘 0.1。路由是固定 balanced
排列，每个 token 的专家 ID 不重复。X、IDs、p、W1、W2、dY 均记录完整哈希；不能把
此输入范围的相等外推为任意尺度、random/hotspot 路由或实际模型的精度保证。

1. 每个场景按 source → candidate → candidate → source 启动独立进程，独立初始化与关闭。
2. 首个 source 窗口先运行一次完整前反向，检查计数和 finite，保存完整输入/输出哈希。
   后三个窗口在 warmup/计时前将其完整哈希与首窗口逐项比较；相等才继续。
3. 每窗口、每阶段预热 5 次、采样 20 次，无 Timer。完整算子 forward 和
   `torch.autograd.grad` backward 使用当前 stream 上的 NPU Event。
4. 每次计时前做分布式 barrier 与 NPU synchronize；反向的准备 forward 在 Event 外。
   不包含 router、loss 构造、optimizer，也不单独测 Python wall time。
5. 共 8 个有效窗口、48 份 rank 记录、1,920 个 rank Event 样本；完整张量比较覆盖 Y、
   dX、dTopK、dW1、dW2。不是独立 CPU 大 shape 全梯度 golden，原 H7168 小 shape
   ptrDX FAIL 仍保留，参见 [精度归因](H7168_ptrDX精度归因.md)。

## 内存记录

每版本取两个窗口、所有 rank 的最大峰值。Torch 峰值统计从输入生成前开始，包含
精度预运行、保存状态、完整反向和测试临时张量，属于该 harness 的 allocator 峰值，
不是算子独占显存或整网训练峰值。reserved 表示缓存分配器保留量。

| 场景 | 版本 | Torch peak allocated / bytes 与 GiB | Torch peak reserved / bytes 与 GiB | 独立 SHMEM / GiB |
| --- | --- | ---: | ---: | ---: |
| EP4 K3 | source | 7075032064 / 6.589137 | 7480541184 / 6.966797 | 3 |
| EP4 K3 | deepep | 7075032064 / 6.589137 | 7480541184 / 6.966797 | 3 |
| EP8 common | source | 6212969984 / 5.786279 | 6425673728 / 5.984375 | 3 |
| EP8 common | deepep | 6212969984 / 5.786279 | 6425673728 / 5.984375 | 3 |

SHMEM 为独立分配，未包含在 Torch allocator 峰值中；驱动、通信和设备缓存的其他内存
也不能由上述数值覆盖。没有将 allocator 峰值与窗口容量简单当作完整进程显存结论。

## 被排除的尝试与未完成项

此前两台节点在检测空闲并启动后出现其他任务的新 NPU 进程，本任务只停止自己的容器，
释放预约，不操作对方进程。第一台已完成 EP4 一组精度对照；两台的未完成性能窗口
均未计入本报告。另一个候选在启动前已被占用，未启动。最终统计仅使用上述同一节点
的完整 8 个窗口，没有跨节点拼接或以历史源分支数字替代本轮数据。

正式 CANN 9.2.0、random/hotspot、其他保存模式的性能、多机/EP 子组、原推理设备回归、
真实框架短训练与长期 loss 收敛仍待专项验收。本轮没有合并 main 或 upstream PR。
