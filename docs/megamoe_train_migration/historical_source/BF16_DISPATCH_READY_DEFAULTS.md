# BF16前反向Dispatch细分的当前默认

> 本文从 `train@6d8f833` 随算法同步。原实验数据属于 train 的历史验证，不能代替本开源分支的验证；本次同步范围与验证见 [2026-10-28 同步记录](BF16_TRAIN_SYNC_20261028.md)。

普通BF16使用默认构建`adaptive-auto`。前向采用M192／Ready384和静态producer元数据，反向saved路径采用M128／256行进度和静态元数据。单行搬运是DMA粒度，与是否等待整专家ready分开选择。

## 前向

新路径对**所有符合条件的非空专家**分别启用细分，不再只选首专家。正常形状要求每卡专家数≤7、`M × TopK ≥ 每卡专家数 × 768`，该专家接收容量截断后的实际行数≥768。none、bf16、mxfp8保存模式共用此选择，SwiGLU解耦的hidden阈值是另一套独立策略。

静态元数据在原`GetCumsumForMMAIV()`的source前缀循环内生成，沿用原pre-Dispatch同步；计算侧按真实producer发布阶段组织M块，AIC与消费GMM1结果的AIV使用相同坐标。没有payload相关的metadata arrival等待，实际行ready及整专家完成flags仍保留。

元数据必须能放入既有GM空闲word、UB与staging空间。当前支持28／32／36 AIC、EP≤256等既有容量条件；不足时回退原首专家选择，不能把它描述成所有shape无条件全细分。容量截断的专家退回原计算映射，实际行ready检查继续保留。小专家仍等整专家。

默认判定可概括为：

```text
静态元数据容量可用且shape满足候选条件：
    每个实际非空专家独立判断：行数>=768用Ready384，否则整专家ready
静态元数据容量不可用：
    回原首个非空专家选择，其余整专家ready
shape不满足候选条件：
    全部整专家ready
```

## 反向

| 保存模式与实际行数 | 默认交付 |
| --- | --- |
| bf16／mxfp8，每卡专家数≤7，专家实际有效行数>128 | 全部符合条件的非空专家细分，256行进度＋原N3配套分核 |
| bf16／mxfp8，每卡专家数≥8 | 整专家ready，保留原3_1分核，不分配细分进度后缀 |
| bf16／mxfp8，专家实际有效行数≤128 | 整专家ready，保留单M保护 |
| none | 原重算＋UB流程，不启用本细分 |

反向元数据在原`RestoreTokenPerExpert()` source循环内分散准备，复用原AIV同步；AIC首次使用时经过一处准备完成等待点，点内仍会轮询，后续不再逐组等待metadata arrival。真实dO行ready、dW完整专家归约、dO复用同步不变。

正常使用不用新增参数。排障可用`MEGAMOE_BF16_BWD_DISPATCH_SPLIT_EXPERTS=0/1/.../all`选择前k个非空专家。默认每卡专家数≤7时为all、≥8时为0；该专家数边界复用前向常量，但实际行数门槛仍各自保留。显式参数是排障覆盖，可在≥8专家时强制all；再逐专家应用单M保护。none始终强制按0处理。

前向仍为M192／Ready384、自适应N条带，反向细分仍为M128／256行producer进度、固定N3和跨组尾块后置，反向整专家仍为3_1。此次只改Host默认选择，不修改kernel算法、发布协议、舍入、同步或原workspace偏移。≥8专家仅不追加细分控制区。

## 范围与验证

前向保持已验证的新M192／384实现，反向保持70207fc的静态元数据实现。两套源码分别通过既有精度与无Timer性能验证；组合另通过六个四卡CPU golden窗口和四个大shape全输出／全部梯度逐位Hash窗口。组合覆盖三种保存模式、clamp、尾块、空专家、不均衡、资源回退，以及K3／常测random。大shape参考复用已有记录，不是新增CPU全梯度golden。未重跑组合性能，不能把独立验证的性能数字冒充新的组合性能。测试脚本、设备记录及debug文档不进入正式源码提交。

EP64／128／256只有离线模型和小EP强制多组精度覆盖，真实设备性能待验证。控制区容量、必要同步及真实数据等待都保留；不宣称任何token分布下都一定提速。

主要代码：`mega_moe_bf16.h`、`mega_moe_bf16_catlass_impl.h`、`forward_prepared_phase.h`、`mega_moe_bf16_backward.h`、`backward_dispatch_schedule.h`。


## 2026-10-25默认专家数边界验证

本次只改Host默认选择，复用相同的普通BF16前反向kernel二进制。8个小shape CPU golden窗口通过；8个大shape场景各先显式all、再用新默认进行完整输出及全部梯度逐位对照，通过后才计时，共16次精度执行、8个配对。返回workspace确认8/16专家不追加16/32KiB细分进度后缀。该大shape验证是同一新Host的策略对照，不是两个Host二进制精度AB。none和7专家原路径保留。

性能在同一新Host中使用显式all复现旧细分默认，与不传参数的新默认按all/default/default/all交错测量；每组warmup10、loops50、无Timer完整反向Event。这个对照测默认策略切换，不是两套Host二进制性能AB。以下正数为新默认更慢，均为两轮最慢rank p50均值之比；完整原始样本与p95保留在本地分析报告。

|保存模式|每卡专家|路由|新默认耗时变化|
|---|---:|---|---|
|bf16|8|balanced|+0.223%|
|bf16|8|random|-0.374%|
|bf16|16|balanced|+0.039%|
|bf16|16|random|+0.158%|
|mxfp8|8|balanced|+0.211%|
|mxfp8|8|random|-0.181%|
|mxfp8|16|balanced|-0.082%|
|mxfp8|16|random|-0.421%|

本轮共32个计时组、12800个rank Event样本。原有每卡8专家约0.2%～0.3%的细分小收益作为统一默认的取舍保留记录，不宣称整专家在所有场景必然更快。大EP没有设备性能保证，热点分布也未穷尽；显式all仍可用于排障和后续验证。

原始组存在少量67～70ms长尾，全部保留。另对MXFP8／8专家／random只补一个同机反序窗口（default/all/all/default），精度再次逐位一致；新默认中位指标变化-0.457%，p95变化+0.140%。该补测未复现70ms样本，但不能据此保证无长尾；不替换原始8组结果，也不对缓存、慢group或通信作未经打点验证的归因。
