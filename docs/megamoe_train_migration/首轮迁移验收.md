# BF16 训练迁移：首轮实施与验收记录

日期：2026-10-28。目标为公开 fork `xixing-321/DeepEP`，开发分支
`feat/megamoe-train-bf16`。代码迁移及下列验证已完成；EP4/EP8 BF16 balanced 性能已于同日补齐，正式 CANN
9.2.0 配套及整网训练仍待验收，不能把本记录理解为全部发布门槛通过。

## 1. 固定来源及实现

- 目标起点：`3a7f692e668e459aac59dfe459ad70a88b14271b`。
- 唯一源：`b8cff14854d12aef77b6ae54b5890123759b4d28`，GitCode `ascend_megamoe_bf16`。
- `experiments/megamoe_train` 与推理 `experiments/megamoe` 同级。Host、kernel、Python、
  测试按 BF16 分开，为后续 W8A8 留出独立实现位置；本轮不交付 W8A8。
- 公共入口 `deep_ep_experimental.megamoe_train.MegaMoeBF16Train`，保留 BF16 前向、
  `dX/dTopK/dW1/dW2`、四种保存模式和 SwiGLU clipping。
- 复用根 Session 唯一 SHMEM owner、窗口与显式关闭；没有第二套初始化/销毁。
- `DEEPEP_BUILD_MEGAMOE_TRAIN=ON`，默认关闭，使用 wheel；与推理开关独立。
- 专用 kernel 导出前缀和直接链接；公开接口不暴露丢弃反向必需数据的选项。
- 保留源版权和许可。`upstream.json` 记录 82 项映射与原哈希；保真检查验证 52 个保留
  C++ 文件。允许已声明的路径、符号、namespace、FFTS 参数替换；忽略格式和注释。
  此检查不能代替数值验证和适配层审查。

没有正式 9.2.0，仅在隔离验证副本中把 CANN 版本声明覆盖为 beta2，覆盖操作单独留证，
实际 SDK 仍做版本及哈希检查。beta2 结果不能代替正式 9.2.0 验收。

数值计算通过源 token 保真检查。正式配套仍需复核此兼容处理。

MTE 初始化是明确的接入差异，**目前只验证单机**。多机传输、EP 子组、更大 EP 和
超节点边界待专项验证；参数允许的上限不等于已经验证的规模。

### 双卡训练精度

`E` 为每 rank 专家数，`F` 为 SwiGLU 后宽度。全部 EP2、TopK4，保留源阈值；检查
两个 rank 的计数、适用中间量和四项梯度。

| M / H / F / E | 保存模式 | clipping | 路由 | 结果 |
| --- | --- | --- | --- | --- |
| 129 / 256 / 512 / 2 | bf16 | 0 | balanced | PASS |
| 129 / 256 / 512 / 2 | none | 0.05 | balanced | PASS |
| 129 / 256 / 512 / 2 | mxfp8 | 0.05 | balanced | PASS |
| 129 / 256 / 512 / 2 | auto | 0 | balanced | PASS |
| 129 / 256 / 512 / 2 | auto | 0.05 | balanced | PASS |
| 65 / 3584 / 3072 / 2 | bf16 | 0 | balanced | PASS |
| 33 / 256 / 512 / 8 | bf16 | 0 | random | PASS，覆盖本地专家数大于 7 的分支 |
| 33 / 256 / 512 / 4 | bf16 | 0 | imbalanced | PASS |
| 65 / 7168 / 4096 / 2 | bf16 | 0 | balanced | ptrDX 原中间量 FAIL；最终四项梯度 PASS |

独立前向 golden：EP2、M1025、H256、F512、E2、TopK4、BF16 保存，输出、专家计数、
保存的 Gate/Up 与打包路由权重通过。两个 rank 输出错误比例均为 0%，不代表逐 bit 全等。

双卡 Gloo 生命周期实测通过：四模式逐次前反向与四次前向后倒序反向逐 bit 相同；
旧权重布局及转回 canonical 的梯度逐 bit 相同；32 次连续前反向后与初始结果相同；
第二个 owner、pending backward 时关闭、跨 stream 调用均被拒绝；重复 close、
关闭后调用拒绝及重新构造正确。32 次重复调用不是整网长稳或 loss 收敛验证。

## 4. 已知问题与未通过项

### 保留的 H7168 ptrDX

源 b8cff148 与迁移版本在原阈值下均为 rank0 **13 / 1,863,680**、rank1
**6 / 1,863,680** 个中间量超阈值点，首次失败坐标相同。其他已检查中间量通过，
最终四项梯度通过源有容错比例的原判据。总用例仍输出 FAIL。

用户已决定本轮保留：未改 kernel 数值、未放宽阈值、未删除失败。已有源版本归因
指向上游 BF16 舍入传播及抵消；这不是实际模型 loss 收敛保证。

### 目标仓原有验证缺口

1. CPU `test_real_tcpstore_local_protocol` 的 `TCPStore(port=0, use_libuv=False)`
   超时。不导入 DeepEP 的独立 PyTorch 程序也复现；固定端口的 Gloo/torchrun 检查通过。
2. 原 `test_dispatch.py` 要求 capability v6，而根 CMake 声明 v7，入口在通信前
   拒绝。两处在目标基线中已如此，未顺带改写其 capability 合同。
3. 原 Combine ST：EP2、tokens17、H7168、experts16、TopK2、normal、repeat2 出现
   vector core exception / retCode 0x31。候选与**独立编译安装、未修改的 3a7f692
   基线**在相同 beta2 环境均复现；基线安装确认没有训练 runtime 工厂。该失败不是
   本次迁移新增，但原有通信设备回归仍不能标为通过。
4. 推理设备精度检查未完成：CPU golden 已生成，设备运行因其他任务占用中断。
   组合包导入成功不能替代推理 kernel 的设备回归。

## 6. 复现和交接

按模块 README 安装 wheel、设置匹配 SDK，从仓库根目录运行：

```bash
python experiments/megamoe_train/scripts/check_source_import.py --ref HEAD
python -m pytest -q tests/runtime experiments/megamoe_train/tests/bf16
python -m pytest -m 'not framework' -q tests/api experiments/megamoe/tests \
  tests/elastic/test_low_latency_host.py tests/elastic/test_ll_st_contract.py
python experiments/megamoe_train/tests/bf16/test_mega_moe_backward.py 0,1 \
  --seq 129 --hidden 256 --gmm-n 1024 --topk 4 --expert-per-rank 2 \
  --routing-mode balanced --save-gmm1-output bf16 --check-intermediates \
  --shmem-ip-port tcp://127.0.0.1:29862
export DEEPEP_SHMEM_ENDPOINT=tcp://127.0.0.1:29862
torchrun --nproc-per-node=2 --master-port=29861 \
  experiments/megamoe_train/tests/integration/bf16_lifecycle.py
```

其余用例按第 3 节替换参数，保留源判据。正式 9.2.0 按仓内锁文件复现，不应静默采用
本次 beta2 覆盖。完整设备日志留在本地交接目录；脱敏的结构化结果放在本临时目录，正式交付整体排除。
